# Corgi TV — MVP 产品需求文档（PRD）

- 版本：V1.0 · 2026-11-02
- 状态：M0已验收；M1–M4已授权；M4播放器、视觉与Docker交付待验收（2026-11-04），测试缺口见m4-test-report.md
- 目标用户：喜欢复古电视、想自己创建频道和排播节目、从桌面浏览器观看的个人用户

## 1. 产品愿景

一台能够由用户自己创建频道、安排每日节目并按真实时间播放的复古互联网电视。**不是通用点播播放器，也不是直播源聚合器。** 用户调台看到的是“这个时刻频道正在播什么”。

## 2. 已确认决策

| 议题 | 结论 |
|---|---|
| 主界面与管理入口 | 主界面只展示复古电视机，机壳具有立体层次；频道、节目、排片和备份在弹窗中管理（2026-11-03确认） |
| 第一版皮肤 | 中国八九十年代 CRT 彩电（真实复古质感） |
| 皮肤扩展 | 作为独立 Skin 模块长期积累，独立于频道/节目核心 |
| 频道 | 用户创建多频道，可编辑、删除、排序、启停；旋钮操作 Prev/Next |
| 节目单 | 每频道独立排片，24 小时、每日固定循环 |
| 时间 | 以 `Asia/Shanghai` 北京时间解释所有节目单 |
| 来源输入 | 手动输入视频链接；M3U8 优先，B站/YouTube 验证后适配；搜索后续迭代 |
| 时序播放 | 从当前时刻相对于排片开始时刻的偏移量播放 |
| 提前播完 | 默认显示无信号；每段排片可选「从头循环」，按现实时间定位到对应轮次，时段结束准时切换。B 站填写当前分集的实际时长后可按时钟循环或切到无信号；未填时长时无法判断片尾 |
| 空档 | 显示皮肤对应无信号屏 |
| 电视交互 | 不向用户提供暂停、快进或播放进度条 |
| 关机 | 释放播放器并停止持续拉流 |
| 开机 | 按当前北京时间重新定位频道节目 |
| 设备 | 电脑浏览器优先，其他终端暂不承诺完整体验 |
| 持久化 | 无业务后端；本地浏览器存储、可导入导出 |
| 技术 | Vite + TypeScript + React + shadcn/ui |

## 3. 用户故事

- 作为用户，我可以创建“经典动画”“纪录片”等频道并修改顺序。
- 作为用户，我可以给频道安排每天 09:00–10:00 的节目并可视化查看节目与空档。
- 作为用户，我在 09:30 打开该频道时看到的是约第 30 分钟的视频，而不是从头播放。
- 作为用户，我能像操作真实老电视一样开关电源、旋转频道和音量旋钮。
- 作为用户，在没有节目、视频提前结束或无法播放时能看到相应无信号/故障画面。
- 作为用户，我关机后不会继续消耗视频拉流流量，刷新或再次打开仍可恢复频道设置。
- 作为用户，我可以导出完整配置为 JSON，并重新导入恢复。

## 4. MVP 功能规格

### F01 电视与皮肤

- 中国八九十年代 CRT 彩电视觉：机身、弧面 4:3 屏幕区域、频道旋钮、音量旋钮、电源键。
- 开机显像、关机、切台短暂闪屏或噪点动画；空档使用彩条无信号 UI。
- 旋钮支持鼠标点击/拖动或滚轮等可发现方式，并能映射到核心频道和音量状态；为可访问性提供键盘替代操作。
- 播放内容显示在电视屏幕指定区域；尽量隐藏原生控件，第三方平台限制以 M0 结果为准。

### F02 频道

- 增删改查、启停、排序。稳定 `id` + 用户可见频道编号；切台根据启用频道顺序循环。
- 不同频道各自拥有排片列表；切台时停止旧播放器并按当前时间定位新频道。
- 无启用频道时显示无信号引导。

### F03 节目资源

- 输入标题、来源类型、URL 或合法来源 ID；可复用到不同排片。
- 支持能力标记：可否 seek、控制音量、获取播放结束事件、销毁等；不满足条件的来源不能承诺完整的电视模式。
- MVP 不做视频搜索、资源抓取、下载、转码、DRM 绕过或后端代理。

### F04 排片工作台

- 每个频道单独显示 00:00–24:00 的横向时间轨道，节目卡片与空档清晰可见。
- 拖动移动、调整节目长度；建议吸附至 5 分钟刻度，并提供精确到分钟的起止输入。
- 同频道禁止排片重叠、允许空档；跨频道同时播出允许。
- 第一版节目不允许跨越午夜（需要拆成两个日内片段）；允许同一视频重复排片。
- 排片修改完成立即保存到本地（带失败提示），并更新当前电视状态。

### F05 时序播出引擎

- **固定时区**：无论设备当前时区为何，计算“北京时间当天时间”。
- 排片判定为 `start <= now < end`；不存在排片时显示无信号。
- 资源起播偏移 = 当前绝对时间与本次排片开始绝对时间之差（毫秒精度），而不是仅计算整数分钟。
- 若偏移大于等于媒体实际时长，按该段「播完后」设置显示无信号或从头循环。新增排片时，已知视频时长则向上取整到分钟预填，可手动覆盖；未知时长不作为可靠的播放结束时间。
- 时段终止时关闭旧播放器、进入下一排片或无信号。
- 切台、重新开机、页签恢复、网络恢复、设备睡眠恢复都重新按时钟定位，避免播出进度逐渐滞后。
- 用户不提供暂停/快进能力，但浏览器可能因策略、网络原因阻止播放；需提供“点击继续收看”等恢复机制。第三方 iframe 是否能完全去除控件以 M0 实测为准。
- 设备本地系统时间可能不准确；V1 不引入服务端可信时间源。

### F06 本地数据

- 频道、节目、排片持久化在 IndexedDB（Dexie）；少量页面偏好可用 localStorage。
- 数据实体详见架构文档；数据 Schema 版本化，以支持迁移。
- JSON 备份包含频道、节目、排片、设置和 `schemaVersion`；导入前验证结构与冲突并提示覆盖风险。
- 本地数据不自动跨设备同步；浏览器清理站点数据可能丢失未备份内容。

## 5. 排片案例与边界规则

| 北京时间/条件 | 预期行为 |
|---|---|
| 08:59，节目 09:00 开始 | 无信号 |
| 09:00–10:00 有节目，09:30 进入 | 跳到约 00:30:00 |
| 09:45，视频长 45 分钟但排到 10:00 | 视频播放结束，至 10:00 无信号 |
| 10:00 有下一排片 | 准时切换；网络加载延迟需明确提示 |
| 10:00 没有下一排片 | 无信号 |
| 次日 09:00 | 重复每日排片，从开头重新播放 |
| 用户关机 | 销毁播放器、停止继续下载片段 |
| 关机后 20 分钟开机 | 直接按新时刻定位，不能续播旧进度 |
| VOD HLS 不支持 seek 或 CORS | 标记不可用或受限，不能错误地从头播放 |
| 直播 HLS 没有历史片段 | 不能保证按时序偏移回看，第一版不作为保证支持对象 |

## 6. 非功能要求

- 播放内容原则上由浏览器直连来源/CDN，不经过 Corgi TV 服务器转发或转码。
- 关机后不应持续触发视频片段请求；网页自身少量请求不等同于视频流。
- 多浏览器实测；首版优先 Chrome/Edge/Safari 的桌面环境。
- 不规避 CORS、DRM、平台鉴权或嵌入限制；仅使用合法授权、允许访问的测试源。
- 浏览器自动播放（特别是带声音）可能需用户主动交互，不能假定随时静默自动播放成功。

## 7. 不在 MVP 范围

- 视频站内搜索、全网检索；AcFun 正式适配；用户账号、云同步、多端一致性；后端 API/数据库；视频代理转码、缓存、抓取下载；手机/电视端专项 UX；多套皮肤；直播时移或历史录制；节目推荐算法。

## 8. 里程碑与发布验收

- **M0**：播放能力验证（先完成，不直接扩建完整产品）。
- **M1**：频道/节目/排片的数据模型、时钟调度器与自动化测试。
- **M2**：八九十年代 CRT 皮肤及旋钮交互。
- **M3**：排片工作台、本地数据及 JSON 备份。
- **M4**：集成回归、静态部署、桌面浏览器验收。

**端到端完成标准**：用户新建两个频道，分别粘贴可用来源链接、按每天不同时段排片；打开电视通过机械旋钮切台，画面按北京时间跳到当前节目进度；空档显示无信号，提前播完按排片设置处理；关机停止拉流；次日重新开机仍按计划播出；刷新不丢数据，JSON 可备份恢复。

> M0 失败不能通过“偷偷增加服务端代理”绕过。须先向用户汇报可行性及产品影响，再决定后续方向。
