## 1. 目标与通过门槛

M0 核心问题：标准 VOD HLS 能否在浏览器直连模式下被加载、跳转到目标时间并被可靠停止；B站、YouTube 官方嵌入对同一场景分别支持到什么程度。

**进入 M1 的必要条件**：

1. 至少一个合法授权、可正常访问、时长足够、支持 seek 的标准 VOD HLS 测试源完成播放→指定偏移定位→结束/停止→销毁闭环；不强求三类来源都完全通过。
2. 视频网络请求直接到第三方源/CDN，不经 Corgi TV 的部署服务器代理。
3. 用户关机/卸载后不持续发出视频片段下载请求；如浏览器缓存、在途请求导致短暂尾流须记录观测窗口和证据。
4. 在模拟北京时间不同播出时刻的场景中，正确计算定位与时段边界；跨页签恢复可重新校准。
5. 20 项任务逐项列出 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN` 与证据；对于不能通过的 B站/YouTube 能力，提供受限设计建议。
6. 向用户提交报告并获得明确确认，才进入 M1。

## 2. 状态定义

- `NOT RUN`：尚未实际执行，绝不能当作通过。
- `PASS`：有浏览器实测结果和可复核证据，符合预设判据。
- `FAIL`：测试已执行，结果不符合判据，记录实际值和复现步骤。
- `BLOCKED`：环境/来源/策略等原因使测试无法完成，记录阻塞原因、已排查事项和解除条件。

所有测试必须区分：**已知 API 文档能力、实测可用、实测不可用、当前无法验证**。示例与参数在某平台有效不等同于持久可用。

## 3. 测试环境与数据准备

- 浏览器：桌面 Chrome、Edge、Safari（实际版本、操作系统及内核记录在报告中）。
- 测试页面：Vite + React + TypeScript 最小页；仅测试播放、偏移、音量、销毁、错误及状态显示。不开发完整电视 UI。
- HLS 测试源：公开合法、点播、支持 CORS、可 seek，**至少 31 分钟**用于 1800 秒位置验证；也可搭配两个测试源分别验证短时与长时场景。若没有合适素材，可通过自有或授权媒体建立合规测试源，但不能为此增加产品级代理。
- B站：选允许官方外链的公开视频；记录 BV 号和受限/失效情况。
- YouTube：选允许嵌入的视频，测试时遵守平台 API、嵌入和自动播放要求。
- 不存储 cookie、令牌、私有 URL 或 API Key 到版本库；必要配置写 `.env.example` 占位。
- 记录 DevTools Network、Console、屏幕录制/截图或自动化结果；播放请求 URL 可脱敏，但要保留域名与经过服务器与否的判断依据。

## 5. 推荐测试方法

### A. 时序测试基准

对每个排片使用固定时区 `Asia/Shanghai` 的真实或注入时钟：

```text
schedule: 09:00:00–10:00:00 Beijing time
entry:    09:30:00 Beijing time
expected: video seek near 1800 s
boundary: 10:00:00 immediately abandon old show
```

用可注入 Clock/模拟时钟测试排片算法；在浏览器实测播放器 seek 结果。不要只验证计算结果就将 M0-14 标记 PASS。加载耗时后按最新时间重新计算偏移。

### B. 关机和断流

开始播放后记录请求 URL、节奏与流量；执行销毁，等待至少 30 秒，观察是否仍发起**新的**视频片段请求。注意已发出的网络请求可能有短暂在途流量，须区分。页面静态资源、网站 favicon、心跳与媒体流分开统计。

### C. 自动播放

区分用户点击“开机”后的播放与没有手势的自动续播；记录浏览器 `play()` 异常和 YouTube 相关状态。不可直接假设未来的定时切节目都能自动带声音播放。

### D. 兼容性

针对 HLS 编码、MP4/CMAF 片段、Safari 原生 HLS、YouTube/B站嵌入和浏览器隐私设置分别说明实际可复现条件，不要求所有来源在所有平台完全一致。
